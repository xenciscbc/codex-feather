# feather-handoff 驗收紀錄

2026-09-08，對照交接規格的四張票驗收。交付是一份獨立 skill 與既有隔離試用入口的交接情境；沒有加入產品執行器、背景服務或專案 AGENTS.md 入口。

## 驗收邊界

離線測試透過既有 CLI 準備 fixture、核對資料與許可寫入範圍，測試正確與不正確產物能否被辨識。這些測試驗證驗收工具，不把人工寫入的測試產物算成 skill 已實際執行。

另由獨立 Agent 讀取候選 skill，在各自隔離專案執行真實使用者指令；根 Agent 再核對產物、原始資料雜湊、Git index／metadata 及回報的實際操作。新 session 接續另用無對話繼承的 Agent，讀取先前另一 Agent 寫出的交接檔。真實操作發生在本次任務的子 Agent 工具執行中；產物檢查不會據手填 review 欄位自動宣稱行為通過。

## 已驗證情境

含先前尚未提交角色調整的工作區，最終完整離線套件 36 項通過（既有 16 項、交接 20 項）。另外匯出本次提交內容、排除先前角色調整，31 項也全部通過，確認本次提交可以獨立使用。Python compileall 與技能 quick_validate 通過。本專案沒有另行配置型別檢查器；compileall 僅代表語法檢查。

| 情境 | 結果與證據 |
| --- | --- |
| 建立與更新 | 明確觸發建一份精簡紀錄；實際 port 7319、未跑測試、下一步與限制均保存。重要進展更新原檔。 |
| 其他 session 的變更 | 在兩輪更新間加入 TLS 限制；後續更新重讀發現並保留，改記 timeout 需求不足而受阻。 |
| 未觸發與名稱 | 一般查詢只回答 port；工作名 history 使用另一合法檔名，既有共同歷史與其他工作保留。 |
| Git 選擇 | 預設忽略；明確選擇追蹤時保持可追蹤；已追蹤工作更新後由 A 成為 AM，index 內容不變。加強 metadata 檢查後用全新試用重跑三種情境。 |
| 讀取與選擇 | 指名讀取只回報；兩項未完成先詢問；只有歷史時回報沒有待接續工作，不讀歷史內容。 |
| 新 session 接續 | 新 Agent 由唯一未完成交接辨識工作並讀來源；另一情境核對過時 /legacy 為 /ready，寫入指定成果並維護原交接。 |
| 正常歸檔 | 涵蓋歷史原先不存在的首次建立與追加既有歷史；保存完成版本、完整讀回核對、重讀原檔後才移除；來源與其他工作不變。 |
| 同名與重試 | 不同完成時間各保留；同一次已保存的紀錄沿用原完成時間，核對正文後只移除原檔，不再次追加。 |
| 歸檔失敗 | 歷史位置是既有目錄時保留原檔；原檔被 Windows 分享鎖占用時，歷史保存成功但移除失敗，保留兩側內容並回報。 |
| 查閱歷史 | 指定日期、全部歷史、沒有匹配紀錄、沒有歷史皆只回報；沒有自動清理或執行歷史中的下一步。 |
| 清除歷史 | 指定完成時間只清除那一筆；同名範圍不明先詢問；全部清除只作用於歷史，未完成工作不變。 |
| 清除失敗 | 以 Windows 分享鎖使歷史無法寫入，Agent 回報失敗並讀回確認逐字未變，沒有終止占用程序。 |

試用產物保存在被 Git 忽略的交接 runs 目錄。失敗故障測試的外部檔案鎖已釋放。部分子 Agent 的寫入需要 sandbox escalation，核准後才重試；核对範圍及來源保護結果，不把 sandbox 名稱當成逐檔權限證據。

## 發現與修正

- 首次試用只寫「已確認 port」，缺少實際值。補強具體結果規則後，重跑能記錄 7319 並保留未驗證狀態。
- Git 情境最初排除 metadata 的範圍太寬，會削弱既有唯讀情境檢查。新增失敗測試後縮至交接 Git 情境，並另核對暫存內容與其他 Git metadata；不能透過 Git 配置副作用讓驗收通過。
- Windows 預設文字編碼會讓技能驗證器無法讀取中文，改以 Python UTF-8 模式執行驗證器；沒有改變技能內容或使用者系統編碼設定。
- Spec 審查指出缺少「歷史尚不存在」的首次歸檔情境。補上先失敗的測試及獨立 Agent 真實操作，確認新歷史完整保存並讀回後才移除原檔；詳見 [兩路審查](handoff-review.md)。
- 釐清交接資料維護與接續工作本身的授權範圍，避免將前者的寫入限制誤套到已授權下一步；新隔離情境重跑接續，仍能核對現況並寫入指定成果。

## 限制

未執行使用者個人目錄安裝、原生 CLI 自動發現或登入式 smoke；不宣稱這些通道已通過。CLI 真實模型測試仍需要明確啟用。此次跨 session 驗證使用獨立 Agent 及實際磁碟交接，沒有讀取帳戶其他任務或搬移登入憑證。

技能仍由 Agent 依規則執行，不是原子交易系統；單次觀察到重讀與正確保存順序，不代表所有多寫入者競態均被排除。
