# feather-handoff 驗收紀錄

同日後續已將新版 skill 納入 Windows／Linux 重建包，位於 `dist/2026-09-09/`。發行包解壓與升級驗收見 [安裝器驗證紀錄](setup-validation.md)；以下保留技能補強當時的測試範圍。

## 完整性與歷史封存補強（2026-09-09）

修正已重現的驗收誤判：原驗收器接受僅含關鍵字、缺少目標／進度／下一步且完成時間不合法的歸檔。現在新增紀錄須有唯一且非空的必要欄位、合法含時區時間、相符的完成與更新時間，以及該工作已知的發現和 timeout 限制；只檢查新增條目，不要求改寫舊歷史格式。重試保留完整已存內容，移除失敗時核對仍存在的最終正文。最終檔案仍無法證明先保存再移除的操作順序，也無法取代任意自然語言內容的語義核對。

交接驗收測試 23 項通過，包含必要欄位缺漏／空白、非法日期／缺少時區／時間不一致、重複狀態、發現或限制遺失，以及封存的完整內容、重試、衝突保留、搜尋唯讀及共同歷史寫入者忙碌時保留完成檔。新增錯誤訊息亦驗證 UTF-8 輸出，並修正既有測試讀取器的編碼設定。skill quick_validate 通過。

獨立子 Agent 只讀候選 skill、各案例使用者請求與原始素材，在 `.scratch/feather-improvements/runs/` 實際執行五種情境；主 Agent 再由公開 `trial.py verify` 核對所有產物及寫入範圍，五項均通過：

| 情境 | 觀察結果 |
| --- | --- |
| seal | 完整 entry 存入 archive/september.md，共同歷史只移除指定 entry；其他工作保留。 |
| seal-retry | 目的檔已存在且相同，只移除共同歷史副本；目的檔不變。 |
| seal-conflict | 目的檔已有不同內容，所有檔案保持不變並回報衝突。 |
| history-writer-busy | 更新完成版工作檔，記下已核對內容與未跑測試；共同歷史不變。 |
| history-search-sealed | 找出僅存在封存的命中紀錄，回報工作／完成時間／路徑；所有檔案不變。 |

首次寫入受 sandbox 限制，獨立 Agent 在未改動資料時停止，核准 escalation 後完成；重試另處理 Windows CRLF/LF 的比較差異。本輪不是 OS 鎖競態測試，也未重建既有二進位發行包或重跑全新 app session 載入驗證。單一歷史寫入者仍為協調規則，不宣稱跨 session 強制鎖定。

## 英文指令重寫（2026-09-08）

來源 skill 已用英文重新組織，共用寫入規則集中管理，操作分為保存、接續、歸檔及歷史。保留既有中文欄位、狀態及歷史分隔格式；欄位內容與回覆跟隨使用者語言。自動發現策略不變。

以 tiktoken 0.14.0 的 `o200k_base`，對換行正規化後的 UTF-8 全文計數：2,116 → 1,106 tokens（減少 47.7%）；description 63 → 31 tokens（減少 50.8%）。這是指定 tokenizer 的比較值，不是目前 Codex 模型的實際用量或其他 tokenizer 的保證。工具與詞表僅放在本機忽略的測試目錄，skill 內容未送到遠端計數。

quick_validate 通過，交接驗收工具 20 項測試通過。獨立 Agent 使用重寫 skill 操作兩個隔離情境：從舊中文交接接續，核對現況並寫出 readiness 成果、保留 timeout 阻礙；對已保存的完成紀錄重試歸檔，只移除原交接，不重複追加歷史。兩項公開 CLI 產物驗收均通過。這是來源 skill 的隔離檢查；先前發行包與四個 app session 的紀錄仍對應重寫前版本，沒有在本輪重建壓縮包或更新測試專案的已安裝版本。

## 驗收邊界

離線測試透過既有 CLI 準備 fixture、核對資料與許可寫入範圍，測試正確與不正確產物能否被辨識。這些測試驗證驗收工具，不把人工寫入的測試產物算成 skill 已實際執行。

另由獨立 Agent 讀取候選 skill，在各自隔離專案執行真實使用者指令；根 Agent 再核對產物、原始資料雜湊、Git index／metadata 及回報的實際操作。新 session 接續另用無對話繼承的 Agent，讀取先前另一 Agent 寫出的交接檔。真實操作發生在本次任務的子 Agent 工具執行中；產物檢查不會據手填 review 欄位自動宣稱行為通過。

含先前尚未提交角色調整的工作區，最終完整離線套件 36 項通過（既有 16 項、交接 20 項）。另外匯出本次提交內容、排除先前角色調整，31 項也全部通過，確認本次提交可以獨立使用。Python compileall 與技能 quick_validate 通過。本專案沒有另行配置型別檢查器；compileall 僅代表語法檢查。

## 發現與修正

- 首次試用只寫「已確認 port」，缺少實際值。補強具體結果規則後，重跑能記錄 7319 並保留未驗證狀態。
- Git 情境最初排除 metadata 的範圍太寬，會削弱既有唯讀情境檢查。新增失敗測試後縮至交接 Git 情境，並另核對暫存內容與其他 Git metadata；不能透過 Git 配置副作用讓驗收通過。
- Windows 預設文字編碼會讓技能驗證器無法讀取中文，改以 Python UTF-8 模式執行驗證器；沒有改變技能內容或使用者系統編碼設定。
- Spec 審查指出缺少「歷史尚不存在」的首次歸檔情境。補上先失敗的測試及獨立 Agent 真實操作，確認新歷史完整保存並讀回後才移除原檔；詳見 [兩路審查](handoff-review.md)。
- 釐清交接資料維護與接續工作本身的授權範圍，避免將前者的寫入限制誤套到已授權下一步；新隔離情境重跑接續，仍能核對現況並寫入指定成果。

## 限制

未執行使用者個人目錄安裝、原生 CLI 自動發現或登入式 smoke；不宣稱這些通道已通過。CLI 真實模型測試仍需要明確啟用。此次跨 session 驗證使用獨立 Agent 及實際磁碟交接，沒有讀取帳戶其他任務或搬移登入憑證。

技能仍由 Agent 依規則執行，不是原子交易系統；單次觀察到重讀與正確保存順序，不代表所有多寫入者競態均被排除。

## 2026-09-11 封存前歸檔收尾檢查

修正歷史已保存但原交接檔刪除失敗時，先封存歷史、再重試歸檔可能重複追加的流程缺口。封存及封存重試須先核對直接交接檔的工作名稱、完成狀態與完成時間；相同身份仍有原檔時保留全部檔案並延後封存，先回報歸檔收尾需求。

新增 `handoff-seal-pending-archive`、`handoff-seal-pending-archive-conflict`、`handoff-seal-pending-archive-retry` 與 `handoff-seal-other-completion`。素材涵蓋不同檔名下的相同完成身份、正文衝突、封存已有副本，以及同名不同完成时间；核對器拒絕在需延後時搬移歷史或刪除原交接檔。

在專案根目錄執行 `python -m unittest discover -s tests -p test_handoff_trial.py`：24 項通過；`python -m unittest discover -s tests -p test_trial.py`：16 項通過。這是離線素材與核對器回歸，新增情境尚未執行原生模型操作驗收，`actual` 保持 `unconfirmed`。
