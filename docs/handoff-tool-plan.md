# Feather 交接工具規劃

狀態：整體規格已確認；已發布 [ready-for-agent 規格](../.scratch/feather-handoff-tool/spec.md)，尚未開始本功能實作。

本文件整合 grill-with-docs 討論中的 Q1–Q15。術語見 [CONTEXT.md](../CONTEXT.md)，架構取捨見 [ADR 0001](adr/0001-handoff-file-tool.md)。本文件描述待實作行為，不代表目前 skill 已具備工具能力。

## 目標與範圍

- 減少 Agent 為列清單而閱讀所有交接全文的成本；允許程式逐檔讀取。
- 第一版不建立主索引或其他持久清單快取，也不新增 `_meta/index.md`。
- 維持 `.feather/handoffs/<工作>.md`、`history.md` 與 `archive/<批次>.md` 的儲存方式。
- 清單預設包含進行中、受阻與完成待歸檔工作；歷史及封存另行查詢。
- 支援不同工作的協調式並行更新；同一工作由單一寫入者維護，共同歷史操作依序處理。
- Claude memory 維持原本的明確選源、唯讀查找規則；本工具不擴大為外部 memory 寫入或匯入工具。

## 責任與執行環境

Agent 負責理解需求、整理進度摘要、判斷工作是否完成、核對實際驗證證據，以及解讀使用者選定的歷史操作範圍。程式負責解析、驗證、列出及保存交接資料，執行歸檔、重試、清除與封存；格式驗證不能證明工作內容或測試結果屬實。

工具以 Python 實作，規劃沿用專案的 Python 3.11+ 基準並只使用標準函式庫。交接工具需要可用的 Python；安裝器執行檔本身不需 Python，兩者需求須分別說明。缺少合適版本時詢問使用者是否要協助安裝，取得同意後依環境處理；不自動安裝或改用 Agent 直接寫檔。未能執行工具時仍可唯讀查閱既有交接，但暫停寫入。

## 交接格式

保留既有 Markdown 欄位名稱及狀態值。新建與獲授權更新的交接，必填欄位各出現一次且有值；時間使用帶時區的 ISO datetime。

```markdown
# config-audit
更新：2026-09-11T15:00:00+08:00
狀態：進行中

目標：核對服務設定。
進度：已核對 port=7319；readiness 尚待確認；未執行測試。
下一步：核對 readiness。
注意：timeout 等待使用者決定。

## 詳細紀錄
按需保留較長的證據、決策背景與其他接續資訊。
```

- `更新`、`狀態`、`目標`、`進度`、`下一步` 為必填；沿用 `進行中／受阻／完成` 狀態值。
- `進度` 即必填進度摘要，由 Agent 在寫入時整理成一至兩句，交代具體進展與主要未完成事項；不另增與它重複的摘要欄位。
- `詳細紀錄` 區段按需保留；既有 `注意`、`環境`、`驗證`、`決策` 等選填內容繼續可用。
- 摘要與自由文字使用使用者語言，機器辨識的欄位名稱、狀態值與時間格式保持固定。
- 允許人工編輯；更新時保留可辨識的額外內容。工具不能藉重新序列化默默刪掉人工補充。
- 舊檔缺少欄位或進度很長，不因查詢而改寫；清單可顯示明確標示的節錄。
- 重複欄位、無法判斷的結構或缺少關鍵資訊，列為格式待確認。Agent 可在已有更新授權且語意明確時整理；有歧義則先詢問，保留原檔。

## 查詢行為

1. 解析專案根目錄，只列舉交接目錄的直接工作 Markdown；排除共同歷史，保留既有合法工作名，不新增 `index` 保留名稱。
2. 程式讀取原檔，清單提供名稱、相對檔案位置、狀態、進度摘要及工作更新時間；同名工作分別列出。
3. 完成但仍有原交接檔的項目顯示完成待歸檔；若實際歸檔情況不明，保留待核對說明。不能只因工作完成便隱藏它，也不能因檔案消失便認定完成。
4. 部分檔案不可讀、格式不明或讀取期間變動，仍列出可確認結果，另列問題檔案及原因並標示清單不完整。變動可有界重試；不能無限等待穩定。
5. 清單是不保證同一瞬間一致的讀取結果。不完整時不能據此宣稱沒有待辦，或自動選定唯一工作。
6. 指定讀取或接續時再讀完整交接；接續仍核對目前專案來源，摘要不是操作授權。
7. 查詢保持唯讀，不修復檔案、不更新 Git 忽略規則，也不執行交接中記錄的下一步。

## 寫入、衝突與失敗恢復

- 所有受管理的交接與歷史寫入走同一工具；Agent 不另走直接改檔的正常路徑。人工編輯仍允許。
- 每項工作由單一寫入者維護；主 Agent 整合協作者的結果再保存。共同歷史的歸檔、清除與封存也由單一寫入者協調，即使它們涉及不同工作。
- 工具讀取時提供內容版本依據，更新前對照原檔；過時寫入停止，由 Agent 重讀整合，有矛盾才詢問。新建時保護既有同名資料。
- 第一版不加鎖。版本檢查與寫入之間仍存在競態，不宣稱能抵禦未協調的其他 session、人工編輯器或舊版 Agent 同時改檔。
- 完成後維持自動歸檔：先保存完成版，保留原完成身份，驗證共同歷史完整保存後才移除相符原檔；失敗保留可恢復資料並回報實際狀態。
- 歸檔重試沿用工作名稱及完成時間，對照完整正文，不重複追加、不重設完成時間；衝突保留並回報。
- 清除與封存依使用者明確選定的範圍處理。封存前核對原交接檔，選定完成身份仍有原檔時延後封存；沿用目前防止歸檔重試重複追加的檢查。
- 歷史查詢／清除預設僅共同歷史，封存內容需明確納入；清除歷史不刪除工作檔。
- 路徑與連結必須核對實際範圍，不覆寫來源或其他工作；無法辨識的既有資料保留。Git 追蹤與忽略行為沿用現有明確選擇，不暫存或提交。

## 實作順序

1. 定義共用解析／保存格式及工具介面，先完成唯讀清單、指定讀取與版本依據；補齊舊格式和部分失敗的測試。
2. 實作建立、更新、完成歸檔及重試，接上內容版本檢查、完整內容保留與失敗恢復。
3. 納入歷史查詢、指定清除及封存，使共同資料操作遵守同一套規則。
4. 更新 skill、使用文件及安裝／檢查流程，讓 helper 隨 skill 部署並檢查 Python 需求；缺少環境時由 Agent 詢問是否協助安裝。
5. 執行離線測試及隔離 Agent 行為驗收，分別記錄成果驗證與實際操作證據，不以靜態通過代替原生行為通過。

命令名稱、模組拆分、版本依據的編碼及清單的排版屬實作細節；按以上規則設計，不再增加獨立資料庫、索引同步或鎖定機制。

## 驗收清單

- [ ] 清單由程式即時產生；Agent 不需讀取所有全文，不建立持久索引。
- [ ] 顯示摘要、同名不同檔案及完成待歸檔項目；已歸檔、封存紀錄不混入預設清單。
- [ ] 舊格式、長進度、額外段落、重複欄位、不可讀檔案與讀取中變動都有明確結果；唯讀操作前後檔案不變。
- [ ] 不完整清單不觸發無待辦／唯一工作的錯誤結論；指定接續仍核對完整原檔與專案來源。
- [ ] 新建不覆蓋既有檔案；過時更新被拒絕，重讀整合後可更新；保留未知但可辨識的人工內容。
- [ ] 不同工作可分別更新；共同歷史依序操作。測試不把版本檢查誤報為無鎖並行安全保證。
- [ ] 首次歸檔、追加、相同身份重試、正文衝突、歷史保存失敗及原檔刪除失敗均保持恢復能力。
- [ ] 歸檔收尾未完成時，首次封存及封存重試都延後；同名不同完成時間仍可按明確選取處理。
- [ ] 清除與封存保留未選定的完整紀錄，重試不重複資料，不改變選取範圍。
- [ ] 路徑越界、連結／別名及既有資料衝突被正確處理；Git 追蹤選擇保持不變。
- [ ] 缺少或版本不符的 Python 會詢問是否協助安裝；拒絕安裝或安裝失敗時不繞過工具寫入。
- [ ] Windows／Linux 的 helper 部署及基本操作經驗證，skill 仍可完整安裝與移除；移除不刪除交接資料。
- [ ] 文件清楚區分已實作、離線通過、原生驗證與未驗證項目。
