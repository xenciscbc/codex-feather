## 已確認

1. 第一版優先服務使用者自己的日常工作。
2. 先交付分工規則、角色模板與隔離測試，安裝器延後。
3. 選角適當、成果可靠即有價值；耗時或用量未下降不直接判定失敗，效率收益仍待實測。
4. 原始碼或邏輯性文件的分析獨立歸類為 analyst，不能由 scout 包辦。
5. analyst 使用 Sol／medium，保持唯讀，提供證據、推論與建議；是否修改及後續行動由主 Agent 決定。
6. 固定角色因此從舊草稿的三種更新為四種：scout、analyst、mech-executor、executor。第一版角色模板範圍隨此決策更新。
7. 是否委派分析由主 Agent 判斷：能切出明確問題與交付成果時可派 analyst；需要持續整合全局資訊、反覆推導同一問題時，由主 Agent 直接處理。分析不強制經過 analyst。
8. 成果回報簡單扼要：先說結果，僅保留必要證據、未確認事項與需要主 Agent 決定的問題；不預設輸出長篇分析或大型表格。

## 已確認的第一版驗收

| 情境 | 預期分工 |
| --- | --- |
| 找設定或符號位置 | scout |
| 分析原始碼或文件中的邏輯與矛盾 | analyst，唯讀回報 |
| 依完整規格批次修改 | mech-executor |
| 需要局部工程判斷的修改 | executor |
| 小任務或難以拆開的整體推理 | 主 Agent 直接完成 |

每種情境檢查選角、成果、權限範圍，以及實際模型與 reasoning 的證據。
耗時與用量先記錄可取得的可信資料，不設節省門檻；取不到執行證據時標示「未確認」。
