# 03: 建立含簡短摘要的交接

Type: task
Status: resolved
Blocked by: 01
Parent: [Feather 交接工具規格](../spec.md)

**What to build:** 使用者明確要求保存工作時，Agent 整理簡短進度與必要詳細內容，經工具驗證後建立交接，立即可在清單中查看。

**涵蓋使用者故事：** 11、12、14、27、38、40、42。

- [x] 只有明確交接要求才建立；Agent 提供具體摘要與真實驗證資訊，工具不自行推斷進度或完成比例。
- [x] 新建保留既有標題及必填欄位，各一次且非空；時間帶時區，狀態採既有值，格式錯誤不產生半成品交接。
- [x] 進度為一至兩句摘要，較長內容存於選填詳細紀錄；既有注意、環境、驗證與決策等內容可以保留，沒有第二個摘要欄位。
- [x] 自由文字可用使用者語言，機器辨識欄位與狀態值保持固定。
- [x] 既有同名資料、保留名稱、路徑越界與來源別名受到保護；不能覆蓋其他工作或專案來源。
- [x] 保存後完整讀回驗證，再經公開清單與指定讀取確認摘要、完整內容及版本依據一致；失敗回報實際殘存狀態。
- [x] 遵守既有 Git 追蹤、忽略及非 Git 專案規則，保留使用者設定，不暫存或提交。
- [x] 建立操作由 skill 透過工具完成；以隔離公開操作驗收建立到列出的完整流程、非法輸入及撞名，並核對無關檔案未變。

**交付邊界：** 本票包含對應的工具行為、skill／使用指引及公開入口驗收；不以只建立內部模組或手寫預期產物代替完整操作。只接管本票已交付的操作，尚未移交的功能保留既有流程；全部票據完成後，規格內的正常受管理寫入均走同一工具。缺少實際平台或 Agent 證據時明列未確認，不把離線產物通過當作行為已通過。


## Answer

新增公開 create 操作，結構化輸入建立簡短進度與完整 details，保存後讀回並可列出。撞名與非法欄位不覆蓋原檔；Git 忽略／追蹤保留選擇、不暫存。公開工具 6 項測試通過。

整體驗收：[工具驗收記錄](../../../docs/handoff-tool-validation.md)。Windows 全套 145 項通過（略過 2）；WSL 新增 31 項通過（略過 3 項 Windows 分享限制測試）。Agent 行為與未確認項目分開記錄，不將離線通過視為全部原生行為已驗證。
