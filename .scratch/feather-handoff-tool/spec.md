# Feather 交接工具：即時清單與統一讀寫

Status: ready-for-agent

## Problem Statement

使用者希望快速列出專案的交接項目與進度。目前 Agent 必須逐一閱讀交接 Markdown，才知道有哪些工作及其狀態；當內容較長時，查詢會消耗不必要的閱讀時間與上下文。

新增主索引雖然能縮短查詢，卻引入索引過時、並行更新互相覆蓋，以及歸檔後殘留或遺漏項目的問題。使用者接受程式逐檔掃描，真正需要減少的是 Agent 的全文閱讀成本。同時，交接仍應保留詳細證據、人工補充及失敗恢復能力，不能為了清單簡短而犧牲接續工作的資訊。

## Solution

提供隨交接 skill 部署的 Python 工具，即時讀取工作交接檔並回傳精簡交接清單，不建立持久索引。Agent 在保存交接時將「進度」整理為一至兩句摘要；清單直接呈現摘要，需要查看或接續指定工作時才讀完整內容。

Agent 負責工作理解、進度內容、完成判斷與使用者授權範圍，工具統一負責解析、驗證與檔案操作，涵蓋建立、更新、完成歸檔、重試、歷史查詢、指定清除及封存。保留 Markdown 人工編輯能力，以單一寫入者協調及內容版本檢查降低覆蓋風險；第一版不加入鎖定。

預設清單包含進行中、受阻及完成待歸檔工作。部分檔案無法確認時仍顯示可讀結果，列出問題檔案與原因，明確標示清單不完整。需要 Python 環境但不可用時，先詢問使用者是否協助安裝。

## User Stories

1. 作為使用者，我希望一次列出專案的交接項目，以便快速了解有哪些工作需要關注。
2. 作為使用者，我希望清單直接顯示簡短進度摘要，以便不用等待 Agent 解讀每份完整交接。
3. 作為使用者，我希望清單依目前原檔即時產生，以便避免持久索引過時造成漏項。
4. 作為使用者，我希望每項包含名稱、檔案位置、狀態與工作更新時間，以便辨識並選取工作。
5. 作為使用者，我希望同名但不同檔案的工作分別列出，以便不被錯誤合併。
6. 作為使用者，我希望進行中與受阻工作都出現在預設清單，以便看見等待處理的阻礙。
7. 作為使用者，我希望完成待歸檔的工作仍然可見，以便知道工作雖已完成但紀錄尚需收尾。
8. 作為使用者，我希望已歸檔與封存的工作另行查詢，以便預設清單保持聚焦。
9. 作為使用者，我希望指定一項工作後能查看完整交接，以便了解摘要以外的證據與限制。
10. 作為使用者，我希望接續前核對原交接與目前專案來源，以便不依過時摘要執行工作。
11. 作為使用者，我希望建立交接時就有具體而簡短的進度，以便以後能直接列出。
12. 作為使用者，我希望較長證據可保留在詳細紀錄中，以便簡短清單不導致交接資訊流失。
13. 作為使用者，我希望重要進展發生時更新同一份交接與摘要，以便避免累積互相矛盾的版本。
14. 作為使用者，我希望目標、下一步、限制與驗證資訊仍可保存，以便下一個 session 有足夠上下文。
15. 作為使用者，我希望能手動編輯 Markdown，以便直接補充工作資訊。
16. 作為使用者，我希望工具更新時保留人工補充，以便不因格式化而遺失內容。
17. 作為使用者，我希望舊交接仍可查閱，以便不必先批次轉換才能使用清單。
18. 作為使用者，我希望舊檔的長進度在清單中明確標示節錄，以便知道尚有未顯示內容。
19. 作為使用者，我希望格式不明的檔案被列為待確認，以便問題不會被默默忽略。
20. 作為使用者，我希望部分讀取失敗時仍能看到其他項目，以便單一檔案不阻斷整次查詢。
21. 作為使用者，我希望不完整清單列出失敗檔案與原因，以便不會誤認為沒有待辦。
22. 作為使用者，我希望查閱不修改檔案、Git 設定或執行記錄中的工作，以便單純查看狀態沒有副作用。
23. 作為使用者，我希望不同工作的更新可以各自進行，以便保留多個 session 處理獨立工作的方式。
24. 作為協作中的主 Agent，我希望同一工作由一個寫入者整合後保存，以便避免不同協作者互相覆蓋。
25. 作為使用者，我希望過時更新被拒絕並交回重讀整合，以便保留其他人的新進度。
26. 作為使用者，我希望語意有歧義的修復先詢問，以便程式或 Agent 不猜測我的意思。
27. 作為使用者，我希望新建交接不覆蓋既有同名資料，以便保護原有工作。
28. 作為使用者，我希望工作完成後自動接續歸檔，以便清單維持目前需要關注的項目。
29. 作為使用者，我希望歷史完整保存並驗證後才移除原交接，以便歸檔不遺失資訊。
30. 作為使用者，我希望歸檔失敗保留可恢復副本並回報實際狀態，以便能安全收尾。
31. 作為使用者，我希望歸檔重試沿用原完成身份且不重複追加，以便歷史保持正確。
32. 作為使用者，我希望相同完成身份但正文不同時回報衝突，以便兩份資料都能保留供判斷。
33. 作為使用者，我希望按名稱、日期或關鍵字查詢歷史，以便找回指定完成紀錄。
34. 作為使用者，我希望只清除明確選定的歷史，以便保留其他完成紀錄與工作交接。
35. 作為使用者，我希望封存保留完整正文、順序及完成身份，以便日後仍能查閱原始歷史。
36. 作為使用者，我希望歸檔尚未收尾時延後相關封存，以便稍後歸檔重試不會重新追加相同紀錄。
37. 作為使用者，我希望清除與封存失敗可重試且不擴大範圍，以便安全恢復操作。
38. 作為使用者，我希望工具尊重專案範圍、其他來源及既有 Git 追蹤選擇，以便交接操作不改動無關資料。
39. 作為使用者，我希望缺少合適 Python 時先詢問是否協助安裝，以便自行決定環境變更。
40. 作為使用者，我希望拒絕安裝時仍可閱讀原交接，但不繞過工具寫入，以便保留一致的寫入規則。
41. 作為使用者，我希望安裝與更新 skill 時一併取得工具，移除 skill 時保留交接資料，以便維持既有部署體驗。
42. 作為維護者，我希望驗收分開呈現程式結果與 Agent 實際操作證據，以便不把離線測試當成整體行為已通過。

## Implementation Decisions

- **架構與資料依據**：工作 Markdown 是正式資料來源，清單即時產生；第一版沒有主索引、持久快取、資料庫或常駐服務。沿用既有專案／工作／共同歷史／封存的範圍，不改變跨 worktree 不自動同步的規則。
- **程式組織**：交接 skill 附帶公開命令工具；共用解析與驗證、查詢、受管理寫入及歷史操作邏輯。沿用現有建置器的整個 skill payload 部署能力，更新安裝檢查與使用說明。模組拆分及命令名稱由實作決定。
- **責任邊界**：Agent 整理摘要、核對證據、判斷完成及使用者選取範圍。程式處理檔案與格式，不自行判斷測試結果是否屬實，不將交接正文當作授權。所有正常受管理寫入使用同一工具，人工編輯仍允許。
- **執行環境**：Python 3.11+，只使用標準函式庫；交接工具的 Python 需求與安裝器可獨立執行的條件分開說明。缺少合適環境由 Agent 詢問是否協助安裝，獲同意後處理。不可執行工具時可唯讀閱讀，不靜默改走直接寫入。
- **格式**：沿用標題及更新、狀態、目標、進度、下一步等必填欄位，各一次且非空；更新時間帶時區，狀態維持既有三個值。進度為一至兩句摘要，不增加第二個摘要欄位；詳細紀錄與既有選填內容按需保留。自由文字採使用者語言，機器辨識欄位與狀態值固定。
- **摘要處理**：由 Agent 在獲授權保存時整理摘要，程式列清單時直接讀取；不推算完成百分比，不以任意截斷取代原交接。舊檔長內容的顯示節錄必須有標示。
- **相容與人工編輯**：保留可辨識的額外內容；唯讀查詢不修復、不轉換。格式無法可靠辨識時列為待確認；已有更新授權且語意明確可由 Agent 整理後交工具保存，有歧義先詢問。未知或衝突的原始內容不得靜默覆蓋。
- **查詢契約**：清單只掃描直接工作檔，預設提供名稱、相對位置、狀態、摘要、更新時間與問題資訊。同名工作分列。完成仍有原檔時顯示完成待歸檔，不因原檔消失推定完成。指定接續再讀完整原檔及相關專案來源。
- **不完整結果**：輸出須明確區分完整清單、完整但無匹配、來源不存在、部分失敗及格式待確認；保留可讀結果與問題定位。觀察到讀取期間變動可有界重試；不保證全目錄同一瞬間快照。不完整結果不得支持無待辦或唯一工作的自動選擇。
- **唯讀邊界**：查詢不改交接、忽略規則或歷史，不執行記錄中的下一步。一般清單不讀歷史及封存；歷史與 Claude memory 維持各自明確觸發的查詢範圍。
- **版本檢查**：讀取提供內容版本依據，更新前對照最新原檔；過時寫入拒絕且保留現況。Agent 重讀整合後再保存，語意衝突交使用者判斷。新建保護既有資料。版本依據的具體編碼由實作決定。
- **並行限制**：每項工作一個寫入者，共同歷史操作也共用一個協調寫入者；不同工作的獨立操作可並行。第一版不加鎖，版本檢查與寫入仍有競態，不提供未協調跨 session 或外部編輯的並行安全保證。
- **完成歸檔**：完成後自動保存完成版再歸檔，完整驗證歷史後才刪除相符原檔。工作名稱與完成時間維持既有重試身份；重試對照完整正文，不重設完成時間或重複追加。失敗保留可恢復資料並回報實際狀態，同身份正文不一致時保留衝突。
- **歷史與封存**：名稱、時間與關鍵字查詢沿用既有規則；日期按指定時區，未指定則說明採用時區。清除僅限明確授權選取，歧義不猜。封存保留完整內容、身份及順序，先保存驗證目的資料再移除相符來源；首次與重試都檢查選定身份是否仍有完成交接檔，有則延後封存。同名但不同完成時間不因此阻擋。
- **安全範圍與恢復**：解析實際路徑及連結／別名，維持專案資料邊界並保護其他來源。尊重 Git 追蹤與忽略選擇，不暫存或提交。受管理寫入須讀回核對，失敗回報實際殘存資料，不擴大刪除範圍。

## Testing Decisions

- **主要測試邊界**：沿用既有隔離 trial 的 prepare／verify 方式，以公開工具命令作為功能入口，檢查回傳結果、結束狀態及隔離目錄的實際檔案變化。既有核對器主要檢查人工建出的預期產物；新增工具驗收必須真正呼叫工具，不能只證明核對器接受手寫結果。
- **好測試的標準**：驗證外部可觀察的行為、資料保留、明確失敗及重試結果，不固定私有函式、模組拆法或內部呼叫次數。短摘要的語意及驗證陳述是否誠實，由 Agent 行為驗收補足。
- **先例**：既有交接測試透過公共 trial 命令準備隔離工作區，檢查所有權範圍、完整正文、完成身份及重試；安裝器測試透過公開命令及隔離 home／project 核對部署。沿用這些邊界與素材，避免新增一套平行測試框架。
- **清單與讀取**：覆蓋無工作、多工作、同名不同檔案、進行中／受阻／完成待歸檔、舊格式、長進度、額外段落、格式損壞、不可讀檔案及觀察到讀取期間變動。檢查摘要與完整性標示，以及所有唯讀操作前後檔案不變。
- **更新與保留**：覆蓋必填欄位、狀態和時間格式、新建撞名、人工額外內容、過時版本拒絕、重讀後成功更新；不能因序列化改寫而遺失內容。不同工作更新及共同歷史順序操作分別驗收，不聲稱版本檢查能消除競態。
- **歷史生命週期**：覆蓋首次歸檔、追加、不同完成身份、相同身份重試、正文衝突、歷史保存失敗、原檔刪除失敗、指定清除與封存重試。驗證完整身份／正文及未選定資料保留，包含歸檔尚未收尾便嘗試封存的連續情境。
- **故障驗證**：優先使用隔離檔案系統可觀察的故障，沿用既有 Windows 分享限制等外部故障注入先例。未施加實際故障時不得宣稱該行為已驗證；需要的最小內部測試輔助不取代公開操作驗收。
- **範圍保護**：涵蓋路徑越界、連結／別名、既有不同資料、Git 追蹤選擇、工作與歷史的範圍隔離，以及查詢不改檔、不讀取不相關來源的行為。
- **部署**：以既有安裝器公開入口驗收 helper 隨 skill 安裝、更新與移除；移除保留交接資料。覆蓋合適 Python、缺少與版本不符的結果，Agent 詢問安裝意願與拒絕後不繞過工具寫入的行為。
- **實際 Agent 行為**：在隔離環境核對摘要整理、使用工具而非直接寫檔、部分結果不誤選工作、接續核對原檔、授權範圍及失敗回報。離線產物通過與原生操作證據分開記錄；缺少證據保持未確認。
- **平台**：驗證 Windows 與 Linux 的公開工具基本行為及部署；無法執行的平台或故障情境明列未驗證，不擴大相容性宣稱。

## Out of Scope

- 持久主索引、索引同步、資料庫、常駐服務與檔案監看。
- 作業系統鎖、鎖定協定、分散式鎖，以及未協調寫入者之間的強一致性保證。
- 自動安裝 Python、繞過使用者意願修改環境，或缺少工具時偷偷改由 Agent 直接寫檔。
- 要求一般使用者使用額外打包的交接工具執行檔；本版採 Python 執行環境需求。
- 舊資料批次自動遷移、唯讀查詢順便修復、強制取消人工編輯能力。
- 重新設計既有歸檔完成身份、跨專案／worktree 自動同步。
- Claude memory 的寫入、匯入、自動接續，以及擴大其現有唯讀來源範圍。
- 由程式判定工作實際完成、證明驗證結果屬實，或自動執行記錄中的下一步。
- 未經使用者選取自動清除或封存歷史。

## Further Notes

本規格根據已確認的 Q1–Q15 與最終整體確認整理，標記 ready-for-agent；發布規格不表示功能已實作或測試已通過。

先前曾提議持久索引與鎖定，均已由後續決策排除。Python 環境需求已接受；缺少時詢問是否協助安裝，不採先前建議的僅回報停止方式。進度摘要沿用既有「進度」欄位，不建立第二份摘要。
