# 06: 整體分工與簡短回報驗收

**What to build:** 使用者能在隔離環境試用完整四角色分工，主 Agent 正確處理依賴、衝突及卡點，整合成果並以簡短說明交付。

**Blocked by:** 02 — analyst 唯讀分析流程；03 — mech-executor 批次修改流程；04 — executor 工程實作流程；05 — 主 Agent 直接處理與通用委派。

**Status:** ready-for-human

- [x] 整合共用規則與四份模板，以同一隔離入口重現查找、分析、機械修改、工程實作及主 Agent 直接處理五種情境。
- [ ] 實際選角符合任務性質，邏輯分析不被 scout 包辦；analyst 保持唯讀，修改決定交回主 Agent。
- [ ] 以可控情境驗證無依賴且無資源衝突的工作可並行；有依賴或寫入衝突的工作依序處理。
- [ ] 子任務阻塞不拖住無依賴工作；規格或能力不匹配時收回、澄清或重新分工，不重複相同失敗派工。
- [ ] 主 Agent 處理成果缺漏與互相矛盾的證據，對最終判斷負責，不能只轉貼結果。
- [x] 成果先說結論，只附必要證據、分工原因、角色、模型／reasoning 確認狀態及待決事項；不強制長篇報告或大型表格。
- [x] 驗證紀錄區分設定與真實執行；缺失證據仍標示未確認，不宣稱完整模型綁定／繼承驗證成功。
- [x] 提供最小手動配置與隔離試用說明，說清生效指令、角色載入、既有同名設定衝突及必要的版本條件；不交付安裝器或遷移工具。
- [x] 不修改真實 Codex home、主模型、reasoning、並行數或既有 hook，不引入額外強制規劃或審查流程。
- [x] 耗時、用量、返工與接手僅記錄可信資料，不設節省門檻；真實模型測試需明確啟用。
