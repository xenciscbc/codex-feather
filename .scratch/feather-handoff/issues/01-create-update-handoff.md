# 01: 建立與更新交接檔

Type: task
Blocked by: None (can start immediately)
Status: resolved

**What to build:** 使用者明確呼叫 feather-handoff 並要求交接後，為目前工作建立精簡交接檔；已啟用的工作在重要進展或受阻時更新同一份紀錄。使用者能控制 Git 追蹤，專案指令入口保持不變。這張票交付第一條可直接呼叫、可驗收的完整流程與後續情境可沿用的隔離驗收能力。

- [x] 提供可明確呼叫的獨立 skill、最小紀錄格式與使用說明；採用規格約定的固定目錄，不插入專案 Agent 指令入口，不交付 feather-setup。
- [x] 首次明確要求交接才建立；一般任務未啟用時不建檔，不啟動背景更新。
- [x] 每項工作維護一份交接檔，同工作跨 session 更新原檔，不同工作保持獨立；名稱可辨識且不覆蓋其他工作或共同歷史，寫入留在約定範圍。
- [x] 紀錄包含名稱、更新時間、狀態、目標、進度與最近驗證結果、下一步，必要時加注意事項；未驗證結果不能標示為通過。
- [x] 重要進展與受阻時保留仍有效的目標及限制，更新目前進度，不累積操作流水帳；沒有注意事項可以省略，不以固定行數截斷必要資訊。
- [x] 更新前若發現另一個 session 的變更，先核對差異並保留有效內容；不能判斷時回報釐清，不以旧內容直接覆蓋，不宣稱多寫入者交易保證。
- [x] Git 預設忽略整個交接資料範圍，使用者明確選擇優先；尊重已追蹤資料，不擅自取消追蹤，保留無關忽略規則；非 Git 專案仍可使用。
- [x] 沿用既有隔離試用入口，加入建立、更新、未啟用、多工作、名稱衝突、他處變更及 Git 選擇的外部行為情境；共用工具若需調整，既有情境保持可用。
- [x] 驗證回覆與產物內容、範圍外檔案及專案指令入口未變；語意觸發與真實 skill 載入以原生操作證據核對，不能只比對提示詞文字或最終檔案。
- [x] 提供可重現的驗收步驟；離線檢查與需明確啟用的真實模型驗收分開，缺少證據時明確記為未確認。
