# feather-handoff：精簡跨 session 交接

Status: ready-for-agent

## Problem Statement

使用者在同一專案開啟新 session 時，需要快速知道先前工作的目標、目前進度與下一步。目前 Feather 提供任務分工規則、角色模板與隔離验收工具，沒有交接 skill；新 session 缺少可直接接續的精簡工作紀錄。

使用者希望明確要求交接後，由 Agent 維護少量 Markdown，而不是備份完整對話或要求人工整理紀錄。未完成工作應容易辨識，完成工作應移入共同歷史，並由使用者決定何時清除、是否納入 Git，以及是否在專案 AGENTS.md 宣告入口。

## Solution

提供獨立的 `feather-handoff` skill，在同一專案、同一份工作目錄中，為每項已啟用交接的工作維護一份精簡交接檔。

使用者首次明確要求交接才建立紀錄；之後在該工作重要進展、受阻或完成時更新。「讀取交接／上次做到哪」僅報告狀態，「接續上次／繼續做」才在核對現況後繼續執行。完成後將最後交接內容追加到共同交接歷史，確認成功後移除原交接檔。歷史只在要求時查閱，只在明確要求時清除。

交接資料預設不納入 Git，但尊重使用者明確選擇與既有追蹤設定。這次不修改使用者專案的 AGENTS.md，入口宣告與其他專案設定留給另行設計的 `feather-setup`，由使用者決定是否採用。

## User Stories

1. As a 使用者, I want 在同一專案的新 session 接續工作, so that 不必重新說明完整背景。
2. As a 使用者, I want 明確要求交接後才建立交接檔, so that 一般對話不會產生無用檔案。
3. As a 使用者, I want 每項工作維護同一份交接檔, so that 不必拼湊多個 session 的紀錄。
4. As a 使用者, I want 不同工作分別記錄, so that 各自的目標與下一步不會混在一起。
5. As a 使用者, I want 交接檔放在專案內固定目錄, so that 新 session 能找到它。
6. As a 使用者, I want 檔案名稱能辨識工作, so that 可以指名讀取或接續。
7. As a 使用者, I want 紀錄包含目標, so that 新 session 知道要完成什麼。
8. As a 使用者, I want 紀錄包含已完成進度與最近驗證結果, so that 不會重做已完成工作或誤認未驗證結果。
9. As a 使用者, I want 紀錄包含明確下一步, so that 新 session 可以快速繼續。
10. As a 使用者, I want 必要時記錄阻礙、限制與關鍵檔案, so that 接續時保留重要背景。
11. As a 使用者, I want 沒有注意事項時省略該欄, so that 紀錄保持精簡。
12. As a 使用者, I want 紀錄包含更新時間與工作狀態, so that 能判斷時效與是否受阻。
13. As a 使用者, I want 已啟用交接的工作在重要進展後更新, so that 不必每次提醒寫紀錄。
14. As a 使用者, I want 更新取代舊進度而非追加操作流水帳, so that 交接檔維持容易閱讀。
15. As a 使用者, I want 新 session 只有在要求交接或接續時才讀取, so that 新工作不會誤用舊進度。
16. As a 使用者, I want 「讀取交接／上次做到哪」只回報狀態, so that 查看資訊不會意外啟動工作。
17. As a 使用者, I want 「接續上次／繼續做」能接著執行, so that 不必再重複授權已明確要求的下一步。
18. As a 使用者, I want 接續前核對相關檔案與目前狀態, so that 過時紀錄不會導致錯誤操作。
19. As a 使用者, I want 可以按工作名稱選擇交接檔, so that 多項工作也能精確接續。
20. As a 使用者, I want 只有一項未完成工作時直接選取, so that 不會被多餘問題打斷。
21. As a 使用者, I want 多項工作無法辨識時先列出名稱詢問, so that Agent 不會僅憑更新時間猜測。
22. As a 使用者, I want 工作完成後移入共用交接歷史, so that 待接續清單只保留未完成工作。
23. As a 使用者, I want 歷史紀錄以工作名稱與完成時間分隔, so that 能辨識同名或不同時間完成的工作。
24. As a 使用者, I want 確認歸檔成功後才移除原交接檔, so that 寫入失敗不會遺失進度。
25. As a 使用者, I want 歷史不在一般接續時自動讀取, so that Agent 只讀目前必要的資訊。
26. As a 使用者, I want 可以明確要求查閱歷史, so that 能回顧已完成工作。
27. As a 使用者, I want 歷史保留到我明確要求清除, so that 不會因檔案大小或時間而自動遺失紀錄。
28. As a 使用者, I want 清除只限我指明的歷史範圍, so that 其他紀錄與未完成工作保持完整。
29. As a 使用者, I want 發現另一個 session 修改紀錄時先核對差異, so that 我的最新進度不會被舊內容覆蓋。
30. As a 使用者, I want 交接資料預設被 Git 忽略, so that 不必為本機工作紀錄處理提交雜訊。
31. As a 使用者, I want 可以自行選擇 Git 追蹤交接資料, so that 團隊需要共享時能使用自己的規則。
32. As a 使用者, I want 呼叫交接 skill 不會插入專案 AGENTS.md 入口, so that 專案指令由我掌控。
33. As a 使用者, I want 專案入口設定交給獨立的 feather-setup, so that 可以另外決定是否啟用。

## Implementation Decisions

- 交付一個獨立的交接 skill，包含必要的使用說明與最小紀錄格式。沿用專案既有交付方式；不引入安裝器、背景程序或新的持久工作流引擎。
- 使用既有領域詞彙「交接檔」與「交接歷史」。同一項工作跨 session 更新同一份交接檔，工作身分不等同於 session 身分。
- 首次建立需要使用者明確表達交接意圖。已啟用的工作在重要進展、受阻或完成時更新；沒有啟用交接的一般任務不自動建立紀錄。
- 自動更新發生在正在執行該工作的 Agent 流程內，不承諾 session 關閉後繼續執行或在新 session 無指令時自動載入。
- 紀錄使用精簡 Markdown，包含工作名稱、更新時間、狀態、目標、進度及最近驗證結果、下一步；必要時加注意事項。狀態使用進行中、受阻、完成。精簡是內容原則，不以固定行數截斷必要資訊。
- 更新交接檔時保留仍有效的目標與限制，改寫目前進度與下一步，不累積逐步操作歷程，不將未驗證結果標示為通過。
- 分開處理狀態查閱與執行接續。單純讀取只報告；接續才核對現況並執行，發現資訊過時時修正。交接內容是工作背景，不擴張使用者授權範圍。
- 選擇順序為使用者指定工作、可辨識的工作名稱、唯一未完成工作。多項未完成且無法辨識時詢問，不以最新更新時間直接猜測。沒有可用紀錄時如實說明，不捏造進度。
- 完成時將最後交接內容加入單一共同歷史，以工作名稱與完成時間作為分隔；確認該次內容已成功保存後，才移除原交接檔。既有歷史保持完整。若中途失敗，保留可恢復內容並回報實際狀態，不宣稱歸檔完成。
- 共同歷史不列入預設待接續候選，也不因一般接續而自動讀取。只有使用者要求查閱時才讀，只有使用者明確要求清除時才清除指定範圍；不設自動到期、輪替或清理。
- 同一工作原則上由一個 session 維護；若發現他處變更，先核對差異再更新，無法判斷時交由使用者釐清。第一版不宣稱具備多寫入者鎖定或交易保證。
- 預設讓交接資料被 Git 忽略，但使用者明確的追蹤選擇優先。既有已追蹤資料不能擅自取消追蹤；保留無關 Git 忽略規則，非 Git 專案仍可使用。
- 不修改專案 Agent 指令入口；獨立 setup skill 才能在使用者選擇後進行設定，本規格不交付該 setup skill。

## Testing Decisions

- 建議以一個最高層的隔離情境驗收邊界涵蓋功能：使用者輸入 → skill 執行 → 回覆、交接資料及實際檔案操作。不要將提示詞特定字串、標題措辭或內部步驟當成行為正確的證據。
- 優先擴充既有 prepare／check／verify 的隔離試用方式，使用已知素材、基準雜湊及情境验收準則；若需加入新測試能力，仍集中在此情境層，不建立第二套測試框架。
- 測試模組為交接 skill 的建立／更新、選取／讀取／接續、完成歸檔／清除及 Git 選擇行為；相關共用測試工具的變更需保持既有情境可用。
- 既有先例是透過命令列測試隔離試用入口，並區分檔案成果驗證與原生操作證據。本規格沿用該區分：只有最終檔案一致，不能證明未讀歷史、未寫後還原、核對過現況或正確解讀了使用者意圖。
- 必驗情境：首次明確交接建立一份紀錄；未啟用工作不建立；同工作更新原檔；不同工作保持獨立；必要欄位足以接續且沒有捏造驗證結果。
- 必驗情境：新 session 從相同目錄讀取；讀取只報告；接續核對現況；明確名稱、唯一未完成、多項不明確、沒有紀錄，以及過時紀錄各自得到預期行為。
- 必驗情境：完成追加共同歷史後移除原檔；既有歷史不被覆蓋；歸檔寫入失敗保留原檔；重試先辨識已保存內容，避免同一次完成被重複追加或誤刪。
- 必驗情境：一般接續排除共同歷史；明確查閱可以讀取；未要求清除時保留；明確清除只影響指定紀錄。部分清除以可辨識的工作與完成時間定位，範圍不明時不猜測。
- 必驗情境：更新前發現另一個 session 的變更時保留其有效內容，無法整合時回報；不以此測試宣稱解決所有競態問題。
- 必驗情境：預設 Git 忽略、使用者明確要求追蹤、資料原已追蹤、非 Git 專案；各情境均保留無關設定，並驗證專案 Agent 指令入口沒有被修改。
- 可自動化的檔案與範圍檢查使用離線測試；語意與真實 skill 載入、跨 session 接續行為以隔離原生執行證據驗收。沿用既有真實模型測試的明確啟用要求，不以靜態檢查宣称整體通過。
- 使用者已確認採用上述隔離情境與外部行為測試邊界；具體測試案例由本規格依已確認的功能行為整理。

## Out of Scope

- `feather-setup` 的設計與實作，以及任何自動插入專案 AGENTS.md 的入口宣告。
- 跨專案、跨 worktree、跨機器的自動發現或同步。
- 每個新 session 自動讀取、所有任務自動建檔、session 關閉後背景更新。
- 完整對話備份、逐步操作流水帳、以 session 為單位保留交接版本。
- 每项完成工作各存一份歷史檔、自動拆分歷史、歷史容量管理、自動清理與到期刪除。
- 多寫入者交易系統、全域工作排程器、資料庫、外部服務或雲端儲存。
- 改動既有角色責任、模型預設、派工規則與子 Agent 權限。

## Further Notes

- 使用者已逐項確認 Q1–Q12；本規格採用最後修訂：歷史先共用、setup 分開做。先前「每项工作各自存入歷史目錄」與「直接加入 AGENTS.md 入口」的提案已不採用。
- 已確認的使用者可見儲存約定：未完成工作的交接檔為 `.feather/handoffs/<工作名稱>.md`；共同交接歷史為 `.feather/handoffs/history.md`。後者是保留名稱，不作為未完成工作交接檔使用。
- 新工作取檔名時不可覆蓋其他工作或共同歷史；名稱如何轉為合法檔名屬於實作細節，以可辨識、留在固定目錄及不覆蓋為準。
- Git 忽略預設涵蓋未完成交接與共同歷史；若使用者已自行決定追蹤，以其選擇為準。
- 現有測試先例位於 `tests/test_trial.py`，隔離入口位於 `scripts/trial.py`，情境與驗收準則位於 `scripts/scenarios.py`。這些是當前實作參考，不要求未來永久維持相同檔案配置。
- 本次交付是規格發布；沒有實作或安裝 skill，沒有啟用真實模型測試，也沒有修改任何使用者專案的入口。
