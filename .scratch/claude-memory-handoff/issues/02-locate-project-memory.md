# 02: 由專案路徑定位 Claude memory

Type: task
Status: resolved
Blocked by: 01

## Parent

[從指定專案的 Claude memory 查找外部交接記錄](../spec.md)

## What to build

使用者指定專案路徑並明確要求查找 Claude memory 時，Agent 能以有效設定、Git 關聯與實際目錄定位來源，再沿用 01 完成交接查找摘要。位置有歧義時列出候選等待選擇，找不到或無法確認時清楚回報；使用者也可直接提供 memory 目錄繼續查找。

本票包含定位規則、使用說明、隔離素材及實際定位到結果的驗收；不以單獨回傳一個目錄名稱作為完成。

## Acceptance criteria

- [x] 明確專案路徑可串接至交接查找與完整結果；不更動 01 的分類、唯讀及觸發規則。
- [x] 實作時核對適用 Claude 版本的官方定位規則並記錄依據；不把本機名稱樣本、字元替換或大小寫猜測視為唯一可靠來源。
- [x] 定位考慮有效的自訂 memory 位置、Claude 設定根目錄及可觀察的專案關聯；讀取設定只用於定位，結果不輸出無關設定內容。
- [x] Git repository 子目錄與 worktree 能找到可確認的共用來源；非 Git 專案也能以專案根目錄定位。
- [x] 多個合理候選或無法消除的設定歧義，列出候選路徑與依據，在使用者選擇前不搜尋任何候選的記憶內容；不依最新時間選擇，也不默默搜尋全部候選。
- [x] 找不到來源、定位資訊不可讀與優先序不明分別如實回報檢查範圍及限制，不把未知位置說成沒有交接。
- [x] 使用者選定候選後，可沿用 01 完成交接摘要；直接提供 memory 目錄時仍以明確指定來源為準。
- [x] 不因來源文字而擴展到其他專案或所有 Claude 記憶，不修改設定、Git metadata 或任何來源。
- [x] 使用說明涵蓋專案路徑、自訂位置、歧義選擇與明確目錄替代方式。
- [x] 既有隔離入口以合成設定與記憶驗證預設／自訂位置、Git 子目錄、worktree、非 Git、候選歧義、缺失及不可讀來源；不使用個人真實記憶測試。
- [x] 核對器及回覆驗收拒絕錯誤來源、無依據選擇與不完整卻宣稱零結果；保留 01 與一般 Feather 讀取回歸。
- [x] 保存 Agent 實際執行「專案路徑到交接摘要」及「歧義等待選擇」的操作證據，核對來源完整性與候選內容在選擇前未被讀取；離線驗證與原生行為分開報告。

## Coverage

主要涵蓋規格使用者故事 2、4–8，並將 01 的來源限制及唯讀保證延伸到定位流程。

## Answer

已完成專案來源定位並接回唯讀查找；規則與官方依據集中在定位參考文件。有效設定優先序、worktree 共用來源與缺少信任狀態的歧義分別處理，明確選定 memory 可繼續查找。

11 項離線素材／核對器測試通過；自訂來源、worktree 子目錄、歧義等待及選擇後續讀的原生工具事件已核對，來源與 Git metadata 不變。非 Git 在 repository 外另有原生驗收；啟動命名及無效設定僅有離線驗收，實際模型 telemetry 未確認。詳見 [驗收紀錄](../../../docs/claude-memory-validation.md)。
