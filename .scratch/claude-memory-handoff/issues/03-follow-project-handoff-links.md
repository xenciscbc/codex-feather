# 03: 讀取 memory 指向的同專案交接檔

Type: task
Status: resolved
Blocked by: 01

## Parent

[從指定專案的 Claude memory 查找外部交接記錄](../spec.md)

## What to build

當 memory 指向指定專案內的交接檔時，Agent 能閱讀該檔案並將交接內容納入摘要與來源清單。跨專案、網頁及無法確認歸屬的連結只列出；錯誤或循環引用不妨礙其他可讀交接的回報。

可用明確 memory 目錄加上指定專案範圍展示與驗收，因此本票只依賴 01，不依賴 02 的自動定位。若 02 已完成，復用其已確認的專案資訊，保持兩種來源輸入一致。

## Acceptance criteria

- [x] 使用者指定 memory 與專案範圍後，memory 明確連結且實際位於該專案內的交接檔會被閱讀，結果沿用 01 的分類、摘要、狀態與來源格式。
- [x] 僅閱讀 memory 明確指向的同專案交接檔，不遍歷整個專案、不跟隨所有文件連結，也不搜尋對話逐字稿。
- [x] 直接 memory 輸入無法確認專案關聯時，仍完成 memory 內查找；目錄外連結只列出並說明缺少已確認的專案範圍，不自行猜測。
- [x] 以解析後的實際目標判斷範圍；相對路徑、路徑跳轉與符號連結不能造成跨專案讀取。
- [x] 跨專案與網頁連結只列來源，不自動讀取；來源中的擴大範圍指令不改變本次查找授權。
- [x] 重複或循環引用不重複展開；同一目標僅回報一次並保留查找來源關係。
- [x] 同專案連結失效、不可讀或內容非交接時如實回報，不捏造摘要；仍呈現其他可讀的符合項目，標示搜尋限制。
- [x] 原文有多項工作或與 memory 本文互相矛盾時保留來源與差異，不自行合併成確定結論或選定接續工作。
- [x] 全程唯讀，不執行記錄中的步驟，不匯入 Feather，不修改連結、交接內容、相關設定或 Git 狀態。
- [x] 使用說明示範同專案交接連結的讀取，以及外部連結、未知專案關聯與部分失敗的回報。
- [x] 既有隔離入口增加同專案、跨專案、網頁、未知歸屬、壞連結、循環、重複及越界目標的合成情境；無法建立的平台特定情境明確標示未測，不假稱通過。
- [x] 保存 Agent 實際閱讀允許交接與僅列出禁止擴展連結的操作證據；對照讀取目標及來源完整性，不能單靠最終檔案未變宣稱範圍合規。
- [x] 驗證直接 memory 與明確專案範圍的完整流程，並保留 01 回歸；02 已存在時追加由專案定位再讀取連結的整合情境。

## Coverage

主要涵蓋規格使用者故事 21–22，並將 01 的多來源、錯誤回報及唯讀保證延伸至同專案交接連結。

## Answer

已完成 memory 明確連結的同專案交接閱讀，保留多來源矛盾與來源關係，未知專案及實際越界目標只列出。Windows junction、未知專案與專案定位後閱讀連結已有原生工具證據；對同專案來源施加真正讀取鎖，確認部分失敗時仍摘要可讀內容。

4 項公開 CLI 核對器測試與 11 項 memory 回歸通過；來源、連結身份、設定與 Git metadata 保持不變。核對器修正等價 Windows 路徑與設定檔引用的誤拒，離線與原生結果分開記錄。詳見 [驗收紀錄](../../../docs/claude-memory-validation.md)。
