# 01: 指定 memory 目錄，找出並摘要外部交接記錄

Type: task
Status: resolved
Blocked by: None (can start immediately)

## Parent

[從指定專案的 Claude memory 查找外部交接記錄](../spec.md)

## What to build

使用者明確指定 Claude memory 目錄後，feather-handoff 能唯讀搜尋其中的 Markdown，依內容辨識外部交接記錄，列出完整摘要、來源、判斷理由與工作狀態。這張票交付從使用者指令到實際查找與回覆的完整流程，並包含使用說明與隔離驗收。

此階段直接使用指定目錄，不自動定位專案 memory；目錄外連結只列出，後續由 03 增加同專案交接檔的閱讀能力。維持既有 Agent 技能交付方式，沿用現有隔離試用入口，不建立另一套產品執行器。

## Acceptance criteria

- [x] 只有使用者明確指定 Claude memory 才觸發；一般 Feather 讀取或沒有待接續項目時，均不自動搜尋外部記憶。
- [x] 使用指定 memory 目錄，不用猜測的預設位置替換；目錄不存在或不可讀時回報實際情況。
- [x] 搜尋目錄內的 Markdown，不只讀索引；索引不存在或遺漏項目時仍能找到其他文件中的交接。
- [x] 依完整相關內容區分明確交接、疑似交接與非交接；無 handoff 檔名的工作進度可被辨識，一般偏好、專案常識或孤立關鍵字不被誤列。
- [x] 每筆結果包含工作標題、明確／疑似判定及理由、未完成／已完成／不明狀態、可定位原文的來源，以及原文記載的目標、進度、下一步與限制；缺少資訊標示未記載。
- [x] 同檔多工作、多份來源與全部狀態皆可呈現，不因時間新舊自行選定工作；重複引用不重複列出，矛盾來源保留並指出差異。
- [x] 區分沒有匹配內容與搜尋不完整；個別文件失敗時回報已查範圍與遺漏，不能宣稱完整零結果。
- [x] 以實際目標界定目錄範圍；符號連結或路徑跳轉不會造成越界讀取。目錄外連結僅列出，不讀取網頁或專案其他文件。
- [x] 全程不建立、修改或刪除 Claude memory、Feather 記錄、專案來源與 Git 設定；不執行原文指令、不接續工作、不匯入交接，也不建立忽略規則。
- [x] 使用說明提供直接指定目錄的範例，清楚解釋分類、狀態、來源與唯讀範圍。
- [x] 沿用既有隔離試用入口增加合成素材與驗收，涵蓋上述正向、負向及既有 Feather 讀取回歸；核對檔案清單、來源內容與相關設定完整性。
- [x] 離線核對器能拒絕漏報、捏造來源與來源變更等不合格結果；自然語言判斷以來源證據驗收，不要求固定措辭。
- [x] 至少有 Agent 在隔離素材實際完成直接目錄查找的證據；從原生操作核對觸發與讀取範圍，將其與離線產物驗證分開記錄，不把雜湊不變當作沒有越界讀取的證明。

## Coverage

主要涵蓋規格使用者故事 1、3、9–20、22–28。專案定位由 02 完成，允許的目錄外連結閱讀由 03 完成。

## Answer

已完成明確 memory 目錄的唯讀讀取分支、使用說明與既有 CLI 隔離驗收延伸。新增核對器測試 5 項及既有 handoff 測試 23 項通過；mypy 與語法檢查通過。四個獨立原生情境驗證直接讀取、多筆矛盾、一般 Feather 不回退及真實讀取失敗。來源未變，讀取範圍另由原生工具事件核對。詳見 [驗收紀錄](../../../docs/claude-memory-validation.md)。

規格審查後另補 empty／missing 原生試跑，分別驗證完整搜尋無匹配與來源不存在，工具事件及來源完整性核對通過。
