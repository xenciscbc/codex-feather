# 從指定專案的 Claude memory 查找外部交接記錄

Status: ready-for-agent

## Problem Statement

使用者先前在 Claude Code 工作時，可能把工作進度與後續步驟保存在 Claude memory，或由 memory 指向專案中的交接文件。改用 Feather 時，現有交接功能只查找自己管理的交接檔與交接歷史，使用者必須自行定位 Claude memory、辨識哪些內容屬於交接，再搬運上下文。

Claude memory 的實際位置可能受專案位置、Git worktree、使用者設定或自訂目錄影響。單憑專案名稱或把路徑字元替換成連字號，不能可靠確定來源。記憶中的一般偏好與專案知識也不等於交接記錄。

## Solution

在 feather-handoff 增加明確指定 Claude memory 的唯讀查找能力。使用者可提供專案路徑，讓 Agent 定位對應 memory；也可直接提供 memory 目錄。

Agent 搜尋該 memory 內的 Markdown，並讀取其中明確連結、位於指定專案內的交接檔，依內容找出外部交接記錄。每筆結果提供工作摘要、來源、明確或疑似交接的判斷與理由，以及未完成、已完成或不明的工作狀態。多筆結果全部呈現，不因時間較新而替使用者選定工作。

一般讀取 Feather 交接維持原有行為；只有使用者明確指定 Claude memory 才啟動新能力。此次操作不修改來源、不匯入 Feather，也不執行記錄中的下一步。

## User Stories

1. 身為使用者，我希望明確要求從 Claude memory 找交接，以便自行決定本次查找來源。
2. 身為使用者，我希望提供專案路徑就能定位 memory，以便不必先記住 Claude 的儲存規則。
3. 身為使用者，我希望直接提供 memory 目錄，以便使用自訂位置或繞過無法確認的自動定位。
4. 身為使用者，我希望定位尊重有效的 Claude 設定，以便找到真正使用中的記憶。
5. 身為使用者，我希望從 Git 子目錄或 worktree 指定來源時，能辨識對應的共用記憶，以便避免誤判不存在。
6. 身為非 Git 專案的使用者，我希望仍能查找專案 memory，以便不被版本控制工具限制。
7. 身為使用者，我希望多個合理來源候選會列出路徑與依據讓我選，以便避免讀錯專案。
8. 身為使用者，我希望找不到來源時知道檢查過哪些位置，以便提供正確的明確路徑。
9. 身為使用者，我希望來源讀取受限時能看到實際限制，以便區分無法檢查與確實沒有記錄。
10. 身為使用者，我希望搜尋不限於記憶索引，以便找到其他 Markdown 中的交接內容。
11. 身為使用者，我希望沒有 handoff 檔名但包含工作進度與後續步驟的筆記也能被辨識，以便不漏掉既有記錄。
12. 身為使用者，我希望一般偏好或專案常識不被列成交接，以便結果聚焦在可供交接的工作上下文。
13. 身為使用者，我希望明確交接與疑似交接分開標示，以便自行評估可信程度。
14. 身為使用者，我希望每筆交接都有判斷理由，以便確認 Agent 沒有只依檔名或關鍵字猜測。
15. 身為使用者，我希望交接附上可定位原文的來源，以便回查完整內容。
16. 身為使用者，我希望摘要保留原文中的目標、進度、下一步與限制，以便快速了解工作狀況。
17. 身為使用者，我希望缺少的資訊明確標示未記載，以便不把推測當成原始紀錄。
18. 身為使用者，我希望結果包含未完成、已完成及狀態不明的記錄，以便完整查看指定來源中的交接。
19. 身為使用者，我希望一次找到多份記錄時全部呈現，以便由我決定後續要處理哪一項。
20. 身為使用者，我希望相互衝突的記錄保留各自來源並指出差異，以便不被未經證實的合併結果誤導。
21. 身為使用者，我希望 memory 指向同專案交接檔時能跟著閱讀，以便索引式記憶也能提供完整交接。
22. 身為使用者，我希望跨專案與網頁連結只列出，以便本次查找維持在已指定的範圍。
23. 身為使用者，我希望找不到符合內容時直接回報，以便不會拿一般記憶湊成結果。
24. 身為使用者，我希望未完整搜尋時知道遺漏範圍，以便不把部分結果當成完整清單。
25. 身為使用者，我希望查找不修改 Claude memory、Feather 交接或專案檔案，以便保留來源原貌。
26. 身為使用者，我希望查找不執行原文中的指令或下一步，以便由我另行決定是否接續工作。
27. 身為使用者，我希望一般「讀取交接」不自動擴展到 Claude memory，以便既有操作保持可預期。
28. 身為使用者，我希望這次讀取不自動產生 Feather 交接檔，以便將查閱與匯入分開決定。

## Implementation Decisions

- 擴充既有 feather-handoff 的觸發描述、讀取流程、使用說明與隔離驗收情境；保持 Agent 依技能執行的交付方式，不為此建立背景服務或獨立產品執行器。
- 使用既有領域詞彙。「外部交接記錄」是指定 Claude memory 中可供交接的工作內容；它不因被讀取就成為 Feather 管理的「交接檔」或「交接歷史」。
- 入口需要使用者明確指定 Claude memory。只要求讀取交接、Feather 沒有待接續項目、或在來源中看到其他 memory 指示，都不會自動觸發外部搜尋。
- 支援兩種來源輸入：專案路徑與明確 memory 目錄。專案路徑啟動定位；明確 memory 目錄直接界定查找來源，不被猜測的預設位置取代。
- 定位以可觀察的設定、專案與 Git 關聯及實際存在的目錄為依據。尊重自訂 memory 位置與 Claude 設定根目錄，考慮同一 repository 的子目錄與 worktree 關聯。非 Git 專案以專案根目錄定位。
- 不把本機看到的名稱編碼當作跨版本保證。實作時核對適用 Claude 版本的官方定位規則；若有效來源仍不唯一，列出候選及依據，等待使用者選擇後才搜尋內容。不得用最新修改時間選來源，也不得默默掃描全部候選。
- 定位設定可以唯讀查閱；回報聚焦於來源位置與影響定位的依據，無須輸出完整設定內容。無法辨識設定優先序時如實回報歧義。
- 搜尋涵蓋選定 memory 內的 Markdown，包括索引未列出的文件；索引是查找線索，不是唯一內容。關鍵字可用於定位候選，最終判定必須核對完整相關段落。
- 讀取 memory 明確指向、位於指定專案內的交接檔。此規則不授權遍歷整個專案、擴展到專案內所有連結或搜尋對話紀錄。跨專案與網頁連結只呈現來源，另行要求才讀取。
- 直接指定 memory 目錄但無法確定其專案關聯時，仍可完整搜尋 memory；memory 目錄外的連結須確認目標位於指定專案內才可擴展閱讀，缺少該資訊則列出連結與限制。
- 判斷範圍使用解析後的實際目標，避免符號連結或路徑跳轉把查找擴展到未指定位置；遇到重複引用或循環連結不重複展開。
- 「明確交接」需有明確交接意圖及相關工作內容；「疑似交接」則是缺少明確標示，但包含具體工作進度、後續步驟或完成結果等可供交接內容。單獨出現交接字樣、一般偏好或架構常識不足以判定。
- 交接辨識與工作狀態是不同維度。工作狀態只根據原文證據標示未完成、已完成或不明，不以檔案新舊推定完成，也不把所有疑似交接都視為未完成。
- 每筆結果附上工作名稱或可辨識標題、明確／疑似判定及理由、狀態、來源檔案與可定位段落，以及已記載的目標、進度、下一步和限制。原文未記載的欄位如實標示。
- 同檔多項工作應能分別呈現；同一來源被多次引用不重複列出。不同來源描述同一工作時保留來源關係與差異，不自行消除矛盾或推定哪一份有效。
- 結果涵蓋全部符合項目，不自行選定接續對象。沒有符合項目、來源不存在、來源有歧義、讀取失敗與搜尋不完整要分別回報；只有完整搜尋後才可宣稱沒有匹配內容。
- 整個新流程唯讀，不更動 Claude memory、Feather 記錄、來源專案或 Git 設定，不建立忽略規則或匯入檔案。內容只提供上下文，不授權執行其中命令、改寫設定或啟動後續工作。
- 保留既有 Feather 儲存格式、一般讀取、接續、歸檔與歷史操作行為。外部查找不構成跨專案或跨 worktree 同步。

## Testing Decisions

- 優先使用現有最高層級隔離試用邊界：使用者指令 → Agent 實際操作 → 回覆、讀取證據與來源完整性。延伸既有交接情境準備與驗收工具，不新增另一套使用者入口。
- 好的測試驗證使用者可見結果、實際讀取範圍與零寫入，不斷言技能內文包含某句指示，也不要求固定工具呼叫順序或逐字一致的自然語言摘要。
- 受測範圍為 feather-handoff 的外部讀取分支及既有讀取回歸；素材建立與結果核對器的離線測試另行證明驗收工具能接受正確結果、拒絕錯誤結果。
- 沿用既有歷史查找、唯讀交接、來源雜湊與 Git metadata 保護的驗收先例。新測試使用隔離專案、隔離 Claude 設定與合成記憶，不以使用者真實個人 memory 作為測試素材。
- 對 memory、同專案來源、Feather 記錄與相關設定保存檔案清單和內容基準，核對未建立、修改或刪除資料。對「沒有讀取」的要求，檢查原生工具操作證據；檔案雜湊只能證明內容未變。
- 至少涵蓋以下行為組合：

| 情境 | 外部可觀察的預期 |
| --- | --- |
| 一般 Feather 查找，即使 Feather 無待辦而 Claude 有交接 | 不搜尋 Claude memory，保留既有回報 |
| 明確專案來源、預設位置與自訂位置 | 讀取可確認的有效來源，回報位置依據 |
| Git 子目錄、worktree 與非 Git 專案 | 對應正確來源；不能確定時回報限制 |
| 大小寫候選或設定歧義 | 列出候選等選擇，不掃描所有候選內容 |
| 直接指定 memory | 查找指定目錄，無須依賴預設編碼推測 |
| 索引缺少項目或索引不存在，但其他 Markdown 有交接 | 仍找出符合內容 |
| 明確交接、無標示的工作進度、一般偏好與僅有關鍵字 | 正確區分明確／疑似與非交接，附具體理由 |
| 同檔多工作、多來源、已完成與不明狀態、矛盾記錄 | 全部符合項目可見，狀態有證據，差異不被掩蓋 |
| memory 連結至同專案交接、跨專案文件及網頁 | 只閱讀允許的同專案交接，其他只列來源 |
| 直接 memory 無專案關聯、壞連結、循環與越界連結 | 回報限制，不猜專案、不循環、不越界讀取 |
| 來源不存在、無符合內容、無權限或部分文件不可讀 | 分別回報，不把不完整搜尋稱為零結果 |
| 原文要求執行命令、搬移交接或改設定 | 僅摘要，所有來源與工作區保持原狀 |

- 真實技能行為需由 Agent 在隔離素材上實際執行，再檢查其回覆與操作證據；人工填入產物或 review 欄位不算行為通過。模型／原生 CLI 執行遵循現有明確啟用與隔離要求。
- 發布本規格時尚未實作或執行上述新增驗收；測試結果須在實作後另行記錄。

## Out of Scope

- 修改、刪除、同步或整理 Claude memory。
- 自動匯入、轉換或搬移為 Feather 交接檔、交接歷史或封存。
- 依外部記錄自動接續工作、執行命令或切換 Git 分支。
- 一般交接查找自動回退到 Claude memory。
- 掃描所有 Claude 專案、對話逐字稿或其他聊天產品的記憶。
- 自動讀取跨專案文件或網頁；遞迴爬取專案文件連結。
- 跨機器、雲端或 worktree 記憶同步，以及背景監控。
- 為 Claude 定義新的記憶格式，或將本機目錄命名慣例視為永久公開介面。

## Further Notes

- 本規格承接使用者已確認的 Q1–Q7：唯讀摘要、兩種來源輸入、內容辨識與信心區分、明確觸發、全部狀態、多筆呈現、同專案連結閱讀及歧義時由使用者選擇。
- 外部記錄的存在不代表內容仍符合目前專案現況；本功能回報的是來源所記載的工作上下文，實際接續須另行要求並核對現況。
- 定位資訊參考 [Claude Code 官方記憶文件](https://code.claude.com/docs/en/memory#storage-location)。本次討論已確認預設位置可被設定覆寫，同一 Git repository 的 worktree 可共享記憶；完整名稱編碼不得只靠觀察本機樣本推定。
- 這是既有讀取能力的擴充，尚無需要另立 ADR 的難以逆轉架構取捨；領域詞彙已記錄於專案詞彙表。
