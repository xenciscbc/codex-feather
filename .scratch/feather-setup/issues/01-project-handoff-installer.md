# 01: 最小可用安裝器：專案交接元件

Type: task
Status: resolved
Blocked by: None (can start immediately)

**What to build:** 使用者取得 Windows x64 或 Linux x64 完整發行包後，可直接執行安裝器，在指定專案檢查、預覽並安裝交接元件。建立後續功能共用的操作紀錄與失敗復原行為，但本票先以不加入入口的交接安裝跑通完整流程。

- [x] 兩個平台均提供可直接執行的安裝器，不要求使用者另裝 Python；發行包包含同版本元件素材與版本清單，安裝不逐項連網下載。
- [x] 完整參數可指定專案目標，預設範圍為專案；解壓位置不決定安裝目標，完整命令不重複確認。
- [x] 檢查與預覽列出目前狀態、目標及預計變更，不寫入元件、設定、入口、備份或安裝紀錄。
- [x] 找到可用 Codex 環境才安裝；不僅以 PATH 是否有命令判斷。缺少環境時回報指引並停止，不代裝 Codex、不處理登入、不留下部分安裝。
- [x] 部署完整交接 skill；本票不加入入口宣告，不建立或改寫交接檔與交接歷史。
- [x] 保存足以辨識元件、版本、範圍、目標與上次安裝內容的紀錄；相同安裝重跑不產生重複內容，来源不明的同名內容回報衝突並保留。
- [x] 修改前完成檢查、計畫與備份；寫入中途失敗時還原本次變更。還原失敗回報實際剩餘變更、備份位置與復原方式，不宣稱成功。
- [x] 以命令到隔離檔案、設定、輸出及退出結果的整合情境驗收，涵蓋正常安裝、重跑、缺少 Codex、同名衝突、寫入失敗及復原失敗。
- [x] Windows 與 Linux 分別驗證實際發行包在無額外 Python 的環境啟動，並取得原生 Codex 發現交接 skill 的證據；不能只用檔案存在宣稱完成載入驗證。

## Comments

沿用既有隔離試用與命令列測試方式。保留既有試用功能；本票不需要先做廣泛重構。

## Answer

完成獨立命令、離線素材打包、專案交接安裝／檢查／預覽、安裝紀錄、完整預檢、原子寫入、備份與失敗復原。來源 CLI 的 10 個整合情境通過（1 個獨立執行檔限定情境略過）；Windows 與 Linux 執行檔各通過 10 個情境（2 個來源 CLI 系統呼叫故障注入情境略過）。原生 Codex prompt-input 確認安裝後 skill 的別名對應實際部署路徑，沒有模型呼叫。mypy 通過。Linux 實測 Ubuntu／WSL2 x86_64、glibc 2.39、Codex 0.153.4；不擴大宣稱其他 Linux 系統相容性。
