# 07: 明確的安裝範圍遷移

Type: task
Status: resolved
Blocked by: 06

**What to build:** 使用者可明確將已安裝元件在專案與使用者範圍之間遷移，先核對来源、目的地與影響，成功部署目的地後才移除受管理來源。

- [x] 遷移必須有明確來源、目的地及所選元件，不由一般安裝時的重複偵測直接觸發。
- [x] 摘要列出將部署與移除的項目；來源為使用者範圍時說明其他專案的能力可見性也會改變，不宣稱只影響目的專案。
- [x] 預先檢查來源所有權、手動修改與目的地同名內容；衝突時保留現況並回報，非互動模式不自行選擇覆寫。
- [x] 目的部署完成且核對成功後才移除所選受管理來源；成功後不留下本次建立的跨範圍同名副本。
- [x] 入口位置仍由使用者獨立選擇；只調整本次明確指定的受管理入口，不因元件遷移擅自改變入口範圍。混合範圍仍保留能力可用條件。
- [x] 來源移除、目的部署、受管理入口與安裝紀錄納入同次復原；目的写入或來源移除失敗時恢復操作前狀態，復原失敗列明差異與備份。
- [x] 以兩個方向的隔離情境驗收，涵蓋來源自訂、目的已有元件、多元件遷移、交接資料保留及各階段失敗；在兩個平台核對成功遷移後的原生發現。

## Comments

06 已包含來源安全移除能力，並透過其前置票帶入兩種範圍與入口規則；遷移不需要等待新版更新功能。


## Answer

已交付 migrate --from/--to，目的完整部署及核對後才移除來源；保留來源版本與位元組。入口預設只轉移所有權，明確指定新範圍才搬動；來源為使用者範圍時摘要列出其他專案可見性影響。同名、未受管理、來源手改及不同環境紀錄均停止。兩平台各 6 項遷移情境通過，涵蓋雙向、多元件、版本保留、目的寫入／來源移除／紀錄提交故障與復原再次失敗。另兩平台使用者 skill 探測各通過 1 項擴充測試，確認整套雙向遷移後 skill 原生位置與入口；Windows 使用真實 OS profile 暫存 skill，完成後已確認不存在。原生角色雙向發現亦通過。型別檢查 12 檔通過。
