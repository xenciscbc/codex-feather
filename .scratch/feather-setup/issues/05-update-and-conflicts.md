# 05: 更新與手動修改衝突處理

Type: task
Status: resolved
Blocked by: 04

**What to build:** 使用者取得新版完整發行包後，可更新所選的已安裝元件、設定與入口，保留手動修改並在明確選擇替換前建立備份。

- [x] 更新從本地新版發行包讀取同版本素材，依安裝紀錄更新所選元件及相關受管理內容，不改動未選元件或要求逐項網路下載。
- [x] 更新前比對上次安裝內容與目前內容，區分可直接更新、已是目標版本、手動修改及來源不明內容。
- [x] 偵測手動修改時保持現況並列出衝突，提供明確保留或替換流程；保留內容不得被標記成已成功替換的新版本。
- [x] 明確替換前保存可取回原內容的備份；一般非互動更新遇到衝突時以非成功結果結束，不等待輸入或隱含覆寫。
- [x] 完整且無衝突的參數直接執行，預覽只列出差異而不套用；重跑相同更新不重複加入內容。
- [x] 多元件、設定與入口更新作為同一次操作；中途失敗還原內容及安裝紀錄，復原失敗列出剩餘變更與備份。
- [x] 以舊版到新版的隔離素材驗證專案、使用者與混合入口更新，涵蓋角色自訂、入口自訂、未選元件保留及多點故障注入。
- [x] 在兩個支援平台驗證發行包更新流程，並核對更新後的原生能力發現；沿用既有情境驗收而非只測版本字串。

## Comments

與 06 同樣依賴 04，可分別實作。共用比對與備份行為應沿用既有操作基礎，不因程式碼共用而要求移除必須等待更新。


## Answer

已交付 update、上次內容與目前／新版內容的可讀差異、--on-conflict keep/replace（預設停止且不寫入）、備份及整體復原。更新維持未選元件版本，處理新版移除的受管理素材，並更新既有跨範圍入口；來源不明的內容不得強制接管。Windows 來源 31 項通過（2 項條件略過）；兩平台實際發行包各執行 5 項更新情境通過（1 項來源故障注入略過），包括更新後原生使用者角色與專案入口發現。Windows 發行包中文差異輸出問題已修正並重驗。
