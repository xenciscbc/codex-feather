# 02: 任務分工與整套安裝

Type: task
Status: resolved
Blocked by: 01

**What to build:** 使用者可在同一安裝器選擇任務分工、交接或整套 Feather，部署所選元件及必要設定，並保留主 Agent 偏好。本票以專案範圍完成元件選擇流程。

- [x] 明確提供任務分工、交接與整套選項；只部署所選元件，不把發行包包含全部素材等同於一律安裝全部。
- [x] 任務分工部署 scout、analyst、mech-executor、executor 的既有角色設定；保留角色責任語意，不另行重設主 Agent 的模型、reasoning 或並行偏好。
- [x] 只合併必要 Codex 設定，保留其他內容；缺少預設已啟用的項目不當作停用，也不為補預設值而無必要地寫入。
- [x] 任務分工與交接使用同一套目標選擇、檢查、預覽、紀錄及重複執行規則；沒有選擇入口時不擅自加入指引。
- [x] 已有同名且無法確認來源的角色或衝突設定時，回報衝突並保留現況，不把它們直接收歸安裝器所有。
- [x] 整套安裝採整體成功；在第二個元件或設定寫入時注入失敗，第一個元件與既有設定也還原到本次操作前的狀態。
- [x] 以隔離情境驗證三種選擇、重複安裝、既有設定保留及多元件失敗；在兩個支援平台驗證發行包與原生 Codex 的角色發現，保留交接情境可用。

## Comments

與 03 可在 01 完成後分別開工；本票不以使用者範圍功能作為先決条件。入口宣告由 04 整合。

## Answer

完成任務分工／交接／整套選擇、四角色原樣部署、主模型與並行設定保留、明確停用 agents 的衝突回報，以及多元件失敗復原。15 個來源 CLI 情境通過（1 個包裝限定略過）；Windows 與 Linux 獨立執行檔各通過 15 個情境（3 個來源系統呼叫注入略過）；mypy 通過。以本機 HTTP 假模型端點捕捉 Codex 送出的原生工具註冊，確認受信任隔離專案中的四角色均被註冊，沒有真實模型呼叫。未受信任專案會略過角色；安裝器不修改信任設定。
