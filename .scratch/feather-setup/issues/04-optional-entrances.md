# 04: 可選入口宣告

Type: task
Status: resolved
Blocked by: 02, 03

**What to build:** 使用者安裝任務分工或交接時，可獨立選擇不加入入口、加入專案入口或使用者入口。指引寫入實際會被載入的目標，並只管理 Feather 區塊。

- [x] 元件範圍與入口範圍分開選擇；選擇不加入入口時不修改任何 Agent 指引。
- [x] 同目錄已有 override 指引時管理該檔，否則使用一般指引；摘要明確顯示實際目標，目標不存在才建立。
- [x] 只加入清楚標記的 Feather 區塊，保留所有區塊外內容；再次安裝不產生重複區塊或指引。
- [x] 入口只宣告已選用能力及其使用條件，保留既有任務分工與交接的責任邊界，不藉由安裝宣告擴張 Agent 權限。
- [x] 支援使用者入口搭配專案元件，明示僅在目前環境具備對應能力時使用；在沒有該元件的其他專案，不要求使用不存在的能力。
- [x] 安裝紀錄包含所管理入口，元件、必要設定與入口納入同次操作的整體復原；入口寫入失敗不留下半套元件部署。
- [x] 既有非本安裝器管理的同名區塊或受管理內容被修改時保留現況並回報，不直接覆寫。
- [x] 整合任務分工、交接及整套在專案／使用者範圍的安裝，驗證一般指引、override 指引、缺少目標檔、重跑及混合範圍。
- [x] 在兩個平台取得原生 Codex 角色、skill 與入口載入證據；對較深層指引、大小限制或信任條件造成的未生效結果如實回報，不自行更改信任設定。

## Comments

02 提供完整元件集合，03 提供使用者與專案範圍規則；兩者都完成才可驗收入口與元件的組合。


## Answer

已交付獨立 --entrance none/project/user、override 選擇、保留區塊外原始位元組、入口所有權與共用參照紀錄。元件、入口與兩處安裝紀錄使用同一次交易；入口衝突與寫入故障不留下半套部署。Windows 與 Linux 25 項入口擴充情境均通過（Windows 2 項、Linux 1 項條件略過），另以範圍矩陣驗證 12 種選項。原生 Codex 證據涵蓋專案 override、使用者入口搭配專案元件，以及另一個沒有元件的專案所見條件式指引；未自行更改真實信任設定。入口摘要明示文件大小、深層指引與信任仍影響載入。
