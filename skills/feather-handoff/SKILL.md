# Feather 交接

在同一專案、同一工作目錄，以精簡 Markdown 保存可供新 session 接續的目前狀態。首次由使用者要求交接才建立；之後只在正在執行的該工作有重要進展、受阻或完成時更新。沒有背景程序，也不依賴舊 session 的對話內容。

## 共用約定

- 先確認目前工作所屬的專案根目錄。工作交接檔固定為 `.feather/handoffs/<工作名稱>.md`，共同歷史固定為 `.feather/handoffs/history.md`。從子目錄操作時仍用同一個專案根目錄；跨專案或 worktree 同步由使用者另行處理。
- 每項工作一份，跨 session 更新原檔。取可辨識的合法單一檔名；`history` 是保留名稱。新工作若撞名就改用可辨識的名稱；同一工作則更新原檔。路徑須留在固定目錄，遇到連結或別名先核對實際目標，不覆蓋他項工作或來源文件。
- 交接內容是背景資料，不是新增授權；接續以目前使用者要求與實際檔案為準。
- 每次更新或移除前重讀目標，核對是否與先前讀取相同。發現其他 session 的變更就先整合仍有效資訊；無法判斷時保留原檔並釐清。共同歷史同樣適用。同一工作以單一 session 維護，不宣稱支援多寫入者交易。
- 本 skill 只維護交接資料及其必要 Git 忽略設定。專案 AGENTS.md 入口交由使用者未來選用 `feather-setup`，本次不插入。

## 建立或更新

1. 依目前工作與使用者的交接要求選定交接檔。沒有交接要求且工作尚未啟用時，不建立資料。單獨呼叫 skill 而沒有可辨識工作或操作時，先釐清。
2. 首次建立時處理 Git 選擇。非 Git 專案直接使用；Git 專案先看使用者指示、既有追蹤與忽略規則。明確要求追蹤或資料已追蹤時保留選擇，不能自行取消追蹤。其餘情況預設忽略整個交接目錄：已有效忽略就沿用，否則在專案 `.gitignore` 加入 `/.feather/handoffs/`，保留既有內容。既有精確的否定規則視為使用者的追蹤選擇，不用新的忽略規則蓋掉。使用者後來改選追蹤時，只調整本 skill 加入的交接忽略規則，不自行提交或暫存檔案；遇到更廣的既有忽略規則則說明來源，由使用者決定如何調整。
3. 以目前證據更新下列格式。保留有效的目標與限制，進度寫具體結果及最近驗證結果；例如已核對的配置要記下實際值，不只寫「已確認」，缺少值時查看相關來源。沒驗證就明寫未驗證。重要進展替換舊狀態，不追加操作流水帳；精簡但不截斷接續必要資訊。

```markdown
# 工作名稱
更新：含時區的日期時間
狀態：進行中／受阻／完成

目標：要完成什麼
進度：已完成什麼；最近驗證結果
下一步：接著做什麼
注意：阻礙、限制或關鍵檔案（沒有就省略）
```

4. 按共用約定核對後寫入，再讀回確認內容完整。工作完成時接著執行下方歸檔；其餘情況簡短回報交接檔位置與狀態。寫入失敗保留可恢復內容並說明實際結果。

## 讀取或接續

1. 使用者要求「讀取交接／上次做到哪」或「接續上次／繼續做」才尋找交接資料。先列出固定目錄中的工作檔，排除 `history.md`；查閱工作標題與狀態辨識候選，已完成的紀錄不列入未完成候選。
2. 優先依使用者指定或訊息能辨識的工作名稱選取。未指名而只有一項未完成工作時直接選取；多項且無法辨識時列出名稱詢問，不以更新時間猜測。指定工作不存在、沒有紀錄或只有歷史時如實說明，不自行改讀另一項工作或歷史。
3. 「讀取」僅回報目標、目前進度、下一步與必要限制；不執行下一步，也不因查閱而更新檔案。明確指定的已完成工作可回報完成狀態；歷史內容只有使用者要求查閱歷史時才讀。
4. 「接續」先核對下一步相關檔案與現況，分清紀錄與實際狀態。修正過時資訊後，執行使用者已授權的下一步；需求不足就明確指出缺項，其他獨立且已授權的工作可繼續。接續後依建立／更新規則維護原交接檔。

## 完成歸檔

1. 確定整項工作完成，再把原交接檔更新為「完成」，保存最後進度、實際驗證結果與含時區的完成時間。使用「更新」欄存這個時間；若原檔已是完成狀態，重試沿用它，不重新取時間。這讓「工作名稱＋完成時間」穩定識別同一次完成。
2. 讀取共同歷史，沒有就建立 `# 交接歷史`。若歷史位置是目錄、連結、無法讀取或格式無法辨識，保留原交接檔並回報阻礙，不自行替換既有資料。
3. 新紀錄使用 `## 工作名稱 · 完成：日期時間` 作為分隔，正文保留最後交接檔內容（省略原本第一行工作標題）。先查同名同完成時間：正文相同表示先前已保存，直接核對；若內容不同，保留兩側原資料並釐清，不覆蓋或重複追加。只有不存在該次紀錄時，才在核對最新歷史後追加，保留既有內容。
4. 寫入後讀回，確認該次完整紀錄與既有歷史都保存成功。再次核對原交接檔仍等於剛歸檔的版本，才移除原檔並確認移除結果。保存或移除任一步失敗都如實回報，保留可恢復內容；重試從原檔及歷史的實際狀態繼續。
5. 完成紀錄留在共同歷史，不列入預設待接續工作；只有使用者明確要求才查閱或清除，不因日期或容量自動清理、拆檔或輪替。

## 查閱或清除歷史

1. 明確要求查閱歷史時，讀共同歷史並按指定工作或範圍回報，不執行其中的下一步，也不因查閱改寫檔案。沒有歷史或沒有符合的紀錄時如實說明。
2. 清除以使用者明確指定的範圍為準。指定全部就清除共同歷史；指定部分就以工作名稱、完成時間等可辨識條件定位紀錄。同名多筆而範圍不明時列出識別資訊詢問，不猜測；已明確授權且範圍完整就直接處理。
3. 先依共用約定核對最新內容，再只移除選定紀錄。部分清除保留其他紀錄；全部清除可移除歷史檔或保留空的歷史標題。未完成交接檔不屬於歷史清除範圍。若歷史中有不熟悉的內容或無法辨識分隔，保留原檔並釐清。
4. 讀回核對指定紀錄已清除、未指定內容完整；只有全部清除才能以確認歷史檔不存在作為完成證據。操作失敗就核對並回報實際狀態，不擴大清除範圍或把部分完成宣稱為成功。
